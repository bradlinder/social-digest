-----------------------------------------------------------------
[x] Mastodon Link Card Parity & Scraper (v5.5.4): Added `card` status object parsing and cached OpenGraph image scraper (`social_get_og_image_cached()`) for Mastodon, ensuring posts with external links render with image preview cards and populate post thumbnails.
[x] Explicit Featured Image Selection UI (v5.5.4): Added "Set as Featured Image" radio control with candidate thumbnail image previews to the Next-Run Workbench, allowing administrators to choose any post image as the digest featured image.

[x] Persist Cutoffs Strictly on Publish & Nonce Audit (v5.5): Verified strict cutoff advancement upon successful publication and verified consistent admin nonce security across all workbench actions.

1. Admin Interface & Workflow Separation (Completed in v5.0.0)
---------------------------------------------------------------
[x] Tabbed Settings & Actions UI: Divided the WordPress admin screen into distinct tabs using standard WordPress `nav-tab-wrapper` (Settings, Editorial & Staging Queue, Actions & Diagnostics). This cleanly separates persistent configuration from operational triggers and diagnostic tests.

2. Editorial Workflow & Staging (Completed in v5.0.0)
------------------------------------------------------
[x] Digest Staging Queue: Interactive approval queue where draft digests can be reviewed before publishing.
[x] Custom Per-Item Commentary: Allows authors to attach custom notes, editorial takes, or takeaways directly above specific social cards.
[x] Per-Post Pinning & Ordering Rules: Allows editors to pin a specific high-impact social update to always appear as the lead story in the digest.
[x] Inline Excerpt Truncation & "Read More" Overrides: Set character fold limit on lengthy updates so one thread does not dominate the entire digest layout.

3. Media Optimization & WordPress Storage Hygiene (Completed in v5.0.0)
------------------------------------------------------------------------
[x] Modern Media Conversion: Automatically converts and compresses sideloaded images to modern formats (.webp / .avif) upon import to save server disk space.
[x] Local Asset & Avatar Caching: Caches remote profile avatars and social embeds locally in WordPress uploads to prevent broken embeds and link rot.
[x] Responsive Image / srcset Preservation: Generates standard WordPress responsive thumbnail sizes (medium, large, medium_large) for fast mobile rendering.

4. Newsletter & Syndication Distribution (Completed in v5.0.0)
---------------------------------------------------------------
[x] RSS-Only Digests: Option to publish digests exclusively to RSS feeds and newsletter campaigns (via `_social_digest_rss_only` meta filtering) without polluting the public homepage blog loop.

5. Admin Health & Diagnostics (Completed in v5.0.0)
----------------------------------------------------
[x] Dry-Run / Simulation Preview: "Simulate Next Run" test engine that inspects active feeds and calculates candidate posts, generated titles, harvested tags, and thumbnail selections non-destructively without modifying database records or timestamps.
[x] Network Connection Diagnostics: Real-time latency and HTTP status indicators for Bluesky and Mastodon API endpoints.

6. Version 5.1 Release Milestone (Completed in v5.1.0, v5.1.1, v5.1.2, v5.1.3, v5.1.4, v5.1.5, v5.1.6 & v5.1.7)
-------------------------------------------------------
[x] Duplicate Resolution Strategies: Configurable cross-posting resolution supporting "Prefer Mastodon if longer, otherwise Bluesky", "Longest text wins", and static network preferences. Compares clean text character lengths excluding hashtags and URLs.
[x] Strict Single-Post Exclusive Resolution (v5.1.2 & v5.1.3): Guarantees that when a duplicate is resolved, ONLY the winning platform's post is embedded in the WordPress post body; the secondary post is completely excluded.
[x] Multi-Signal Detection & Tag Harvesting (v5.1.3): Resolved cross-post detection for truncated posts and link cards via URL stem matching, prefix/substring containment, and relative text similarity. Intelligently harvests tags from the losing post to enrich WordPress taxonomy if the winning post lacks them.
[x] Dry-Run Simulation Null-Safety & Fallback Resilience (v5.1.4): Hardened simulation preview rendering to prevent PHP 8 null-offset TypeError exceptions and enabled automatic recent post inspection during dry-runs.
[x] Runtime Exception Hardening & Schema Validation (v5.1.5): Wrapped dry-run simulation and background ingestion in top-level Throwable handlers with actionable admin notices, fixed callback compatibility in URL cleaners and tag formatters, and added null-safety validation across API payloads.
[x] CamelCase Title Tag Preservation (v5.1.6): Refined tag formatting regex to preserve words with single lowercase character prefixes (e.g. #iPhone, #eReader, #iPad, #eBay, #iOS, #eBook) rather than splitting them into separate words in post titles.
[x] Live Staged Article Preview (v5.1.7): Embedded real-time compiled post article mockup inside the Editorial & Staging Queue, rendering custom editorial takeaways, pinned lead stories, header/footer framing, and media embeds as staged items are edited.
[x] Real-Time Staging Workbench: Interactive editorial review workspace with inline commentary framing, priority reordering, and immediate early publish capability.
[x] Ephemeral Post Mockup Inspection: Interactive simulation inspector that renders full card mockups, tag taxonomy rankings, deduplication badges, and media selections on demand.
[x] Full WordPress 6.x UI Fidelity: Synchronized Admin Bar, settings tab navigation, and live published post preview across both Admin and Front-End views.

9. Workbench Stabilization & Architectural Hardening (Planned)
--------------------------------------------------------------
Phase 1 — Critical Fixes (Blocking, Prioritized for Next Release)
[ ] Persist Cutoff Timestamps on Publish:
    - In `social_fetch_workbench_candidates()`, after a successful publish (not on mere fetch/preview), call `update_option('bsky_last_digest_time', $new_bsky)` and `update_option('masto_last_digest_time', $new_masto)`.
    - Advance cutoffs only when the run actually publishes — inside `social_publish_workbench_run()` on success — not at fetch time, so a discarded/unpublished fetch never causes posts to be silently skipped later.
    - Test: fetch -> publish -> refresh again, and confirm the same posts don't reappear as candidates.
[ ] Fix Nonce Action Mismatches:
    - Change `check_admin_referer('sd53_manual_run', 'sd53_nonce')` -> `check_admin_referer('sd53_workbench_action', 'sd53_nonce')`.
    - Same fix for `check_admin_referer('sd53_reset_cutoff', 'sd53_nonce')`.
    - Test: click "Run Standard Automated Import Now" and "Clear Cutoff Markers" and confirm neither hits the "Are you sure?" die screen.

Phase 2 — Architectural Decisions & Collision Prevention
[ ] Cron vs. Manual Staging Collision Prevention (Option A: Mutually Exclusive by Policy):
    - Document clearly (in settings screen and/or README) that scheduling and manual workbench curation are not meant to run concurrently: if staging by hand, turn the schedule off until published or discarded.
    - Add a visible warning notice in the Workbench tab when a schedule is active and unpublished candidates exist in `social_digest_next_run` (e.g. "A schedule is active and will overwrite this draft when it next fires. Disable scheduling before curating, or publish/discard this draft first.").

Phase 3 — Editorial Workflow Improvements
[ ] Refresh Confirmation Dialog:
    - Add a JS `confirm()` on "Refresh / Fetch Next Run" button (e.g., "Refreshing will discard your current exclusions, pin, and notes — continue?") so data loss is explicit rather than silent.
    - Only prompt when there is existing state to lose (skip confirmation if candidate list is empty or unchanged from defaults).
[ ] Candidate Key Stability:
    - Low priority evaluation; revisit only if preservation-on-refresh across candidate pools is desired later (not needed for confirm-dialog approach).

Phase 4 — Polish & Hygiene
[ ] Harmonize `network_mode` Default:
    - Ensure settings tab displayed fallback matches registered setting default (`'both'`), eliminating stray `'bsky'` fallbacks.
[ ] Remove Dead Code:
    - Strip `delete_transient('social_digest_simulation_data')` from `social_clear_workbench_state()` as simulation data transient is deprecated in state machine architecture.
